## Overview

The DAM is a personal photo Digital Asset Management system built on Python/Flask/SQLite with AI-powered tagging (LLaVA 34b → dam-tagger Mistral 7B LoRA → nomic-embed-text embeddings), burst stacking, card ingestion with checksum verification, and semantic search via sqlite-vec.

The architecture is clean, the module separation is solid, and the safety discipline around file operations is production-grade. The issues found are minor — one live bug, several performance concerns, and standard engineering hygiene improvements.

## BUGS (Fix Immediately)

### 1. Route parameter mismatch in dam_api.py

**Severity:** Breaking — these endpoints will 500 on every call.

```python
# Line ~477: Route param is <n>, function param is `name`
@app.route("/api/images/<int:image_id>/projects/<n>", methods=["DELETE"])
def image_remove_project(image_id, name):  # should be `n` or route should be `<name>`

# Same bug on subjects:
@app.route("/api/images/<int:image_id>/subjects/<n>", methods=["DELETE"])
def image_remove_subject(image_id, name):
```

**Fix:** Change `<n>` to `<name>` in both route decorators, or change the function parameter to `n`.

## PERFORMANCE ISSUES

### 2. `images_flat` view is a join bomb

The view joins `images`, `image_projects`, `projects`, `image_subjects`, `subjects`, `image_keywords`, and `keywords` with `json_group_array` and `GROUP BY i.id`. Every query against it processes the full join before filtering.

**Recommendation:** Drop the view. Use the inline join pattern from `/api/images` everywhere. Create a helper function `_image_detail_query(where, params)` to avoid duplication.

### 3. `_migrate_storage_identity` runs on every startup

`init_db()` is called on every module import. The migration function fetches ALL rows to check volume/relative_path backfilling. Once migration is complete, this is pure waste on 50k+ rows.

**Fix:** Use `PRAGMA user_version` as a schema version tracker:

```python
def init_db():
    conn = get_db()
    conn.executescript(SCHEMA_SQL)
    version = conn.execute("PRAGMA user_version").fetchone()[0]
    if version < 1:
        _migrate_storage_identity(conn)
        conn.execute("PRAGMA user_version = 1")
    conn.commit()
    return conn
```

### 4. No WAL checkpoint management

WAL mode is enabled (good), but with gunicorn workers + background tagger processes writing concurrently, the WAL file can grow unbounded.

**Fix:** Add `PRAGMA wal_checkpoint(TRUNCATE)` after bulk operations.

### 5. Missing partial index for untagged images

**Fix:** Add to schema:
```sql
CREATE INDEX IF NOT EXISTS idx_untagged ON images(id) WHERE ai_description IS NULL;
```

## CODE HYGIENE

### 6. `serialize_vector` is duplicated

Exists identically in both `dam_tagger.py` and `dam_api.py`.

**Fix:** Move to `dam_db.py` as a shared utility.

### 7. No connection context manager

Every API route manually calls `get_db()` and `db.close()` in try/finally.

**Fix:** Add context manager to `dam_db.py` and use Flask `g` + `teardown_appcontext` pattern.

### 8. `spawn_background_process` potential file handle leak

Log file handle is opened, passed to Popen, then immediately closed in the parent.

**Fix:** Let Popen manage the file handle lifecycle.

### 9. MD5 for checksum verification

**Fix:** Swap `"md5"` → `"sha256"` in `card_ingest.py`. Negligible performance difference.

### 10. No recovery path for stuck ingests

If `ingest_status.json` shows "copying" and the process died, status stays stuck.

**Fix:** Add stale-status detection or `--reset-status` CLI flag.

### 11. Sony A7C II camera mapping missing

`CAMERA_SHORT_MAP` doesn't include ILCE-7CM2. Add `"ILCE-7CM2": "A7CII"` and `"A7CII": "E-mount"`.
