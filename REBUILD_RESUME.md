# DAM Rebuild — Handoff at End of Sprint
**Updated: 2026-05-13, after Phases 4, C, and v0.5 vocab.**

## Where we ended up

The rebuild is **operational end-to-end except for descriptions** (Qwen). The pipeline runs SigLIP for both image embeddings and zero-shot classification; the GUI's search box and grid use the new path. Old LLaVA-era descriptions and tags remain in the DB as historical data, distinguished from new classifier output by the `confidence` column on `image_keywords`.

### What's live right now
- **`/api/search`** uses SigLIP text encoder against `image_embeddings_siglip` (1152-dim). Sub-100ms warm latency. Three live queries validated.
- **54,987 of 56,117 images** have SigLIP embeddings + classifier tags (98.0% coverage; 1,130 RAF files lack PIL-readable previews, fixable separately).
- **Grid + search pages** return up to 1,000 results (bumped from 200).
- **Vocabulary at v0.5**: 283 tags. Mood projections (`distress`, `cozy`, `concern`, `excitement`, `relaxation`, etc.) filtered out of classifier output. Confirmed clean: zero new classifier rows for any of those leakers.
- **397,173 classifier tag rows** with confidence scores. Average 7.2 tags/image.

### What's still legacy and lingering
- **`ai_description`** column holds either LLaVA-era output or Qwen-era output from your earlier 188-image test. None of it has been generated by the new pipeline.
- **366,799 legacy keyword rows** with `confidence IS NULL`. Most are concrete and good. Some (`intimacy` 11,147 rows, `relaxation` 329, `dramatic` 58) are projected moods baked in before the new classifier. The GUI mixes legacy + classifier output in the keyword display without distinguishing.

### 🔲 Phase 8 — Kick off Qwen on the 54,987 images
~12.5 days at 18s/image. Resumable via `described_at IS NULL` partial index. Per-image commit. Memory footprint ~22 GB resident during inference, ~6 GB between batches.

### 🔲 Legacy tag cleanup (decision pending)
Tomorrow's question: do nothing, hide legacy tags from UI, or surgically delete the worst mood projections from `image_keywords WHERE confidence IS NULL`. My lean: hide in UI for now, decide later whether to delete. Deletion is destructive; hiding is reversible.

### 🔲 1,130 RAF backfill
Fuji RAF files have RAW thumbnails PIL can't open natively. To close the 98% → 100% gap, regenerate previews for those 1,130 images via existing `generate_preview` (which uses `exiftool -b`), then rerun `bootstrap_siglip.py`. ~10 minutes of work.

### 🔲 Keyword + keyword search in the search box
Currently the search box only does SigLIP semantic. The filter sidebar can chain `?keyword=child&keyword=sleeping` for tag-intersection. A future enhancement is parsing the search query into "tag tokens" + "semantic remainder" — e.g. `child sleeping warm light` → intersect tag `warm light` if it's in vocabulary, semantic-search remainder. Out of scope for this sprint.

### 🔲 Preview route silent except → real error logging
`dam_api.py` `/api/previews/<id>.jpg` hides three failure modes behind one fallback to thumbnail. The "lightbox sometimes serves thumbnail" UX bug is rooted here. Fix is a `try/except Exception as e: log.warning(...)` change plus an `X-DAM-Preview-Source` response header so the frontend can show a badge when fallback fired.
